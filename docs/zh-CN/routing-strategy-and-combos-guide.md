# 10Router 路由调度策略与多账号分发指南

> 本文档面向 10Router 用户与开发者，系统阐述全局路由策略（顺序、轮询）、多账号「到期优先调度」、以及模型组合（Combos）的四种高级路由模式（回退、轮询、融合、决策路由）的运作机制、生效层级与最佳实践。

---

## 一、 核心调度策略金字塔（执行优先级）

在 10Router 网关发起任何推理请求时，系统严格按照以下**三层金字塔**来决策由哪个账号或模型响应：

```text
▲
│  【第 1 层：请求显式指定】 (最高优先级)
│  客户端或调用方在请求头/参数中显式指定 connectionId 或 pinned 模型
│  └─► 直接使用该账号，短路跳过所有算法
│
│  【第 2 层：供应商级策略】 (覆盖全局默认)
│  如果在具体的供应商卡片上配置了独立策略：
│  ├─ 开启「到期优先调度」 ──► 100% 流量优先打快到期的账号，接管并禁用轮询！
│  └─ 开启该供应商的专属「轮询」/「顺序」
│
│  【第 3 层：系统全局默认策略】 (底线兜底)
│  在「个人设置 → 路由策略」中配置的全局默认：
│  ├─ 顺序（Fill-First）：永远优先打 #1 号，遇到限流或故障再顺位降级
│  └─ 轮询（Round-Robin）：按设置的粘性次数（Sticky）在可用账号间平均分摊
▼
```

## 二、 多账号分发策略深度对比

### 1. 顺序（优先填满，Fill-First）
- **适用场景**：主副号分明、希望集中用完某一特定凭据的场景。
- **机制**：
  - 流量始终打在优先级为 `#1` 的账号上；
  - 只有当 `#1` 账号触发 429（限流）、401/403（凭证失效）或被标记冷却时，网关才会将当前请求平滑降级（Fallback）给 `#2` 账号；
  - 一旦高优先级账号冷却期结束恢复健康，流量自动切回。

### 2. 轮询（负载分摊，Round-Robin）
- **适用场景**：多把官方付费 API Key、企业团队密钥、无到期压力的永久额度账号。
- **机制**：
  - 雨露均沾，在所有活跃账号间轮换；
  - **粘性限制 (Sticky Limit)**：为了利用上游的上下文缓存（Prompt Cache），可以设置每个账号连续使用 $N$ 次（默认 3 次）再换下一个账号，兼顾负载均衡与缓存命中率。

### 3. 到期优先调度（Earliest Expiry First）
- **适用场景**：**CodeBuddy CN 体验包、Qoder 活动赠送包、限时免费额度、即将过期的促销代金券**。
- **为什么它与轮询互斥？**
  - **商业目标冲突**：轮询是“平均摊薄”，到期优先是“抢救资产”；
  - 如果多个账号都有即将过期的积分包，执行轮询会导致每个账号各消耗一点，结果**快过期的账号额度没用完就全部作废了**；
  - 因此，**开启「到期优先调度」后，系统会自动禁用并置灰「轮询」**，将全部火力集中消耗最紧迫即将过期的账号；
- **核心算法设计**：
  - **存活判定**：已耗尽（0分）的赠送包自动退出计算，绝不劫持到期日；
  - **动态队列**：按账号存活包的最早到期时间（如 10天 -> 15天 -> 26天）严格升序排列，只烧最前排账号；
  - **安全保护**：到期时间充裕的账号（如 26 天后到期）自动被挂起保护，杜绝跨级透支。

## 三、 模型组合（Combos）四大路由模式

模型组合（Combos）允许你将不同供应商、不同家族的模型聚合为一个统一的模型别名（例如 `smart-coder` 或 `glm-5.3-flash`）。在组合卡片右上角，提供了四种策略：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        组合策略对比 (Combos)                            │
├─────────────┬─────────────────────┬──────────────┬─────────────────────┤
│ 策略模式    │ 运作机制            │ 费用与调用量 │ 适用场景            │
├─────────────┼─────────────────────┼──────────────┼─────────────────────┤
│ 回退 (Fallback)  │ 按列表顺序依次尝试，│ 仅计费成功的 │ 默认最稳妥，高可用  │
│             │ 失败时平滑切下一个   │ 那 1 次调用  │ 容灾备用            │
├─────────────┼─────────────────────┼──────────────┼─────────────────────┤
│ 轮询 (Round-Robin)│ 每次请求轮换不同成员│ 仅计费选中的 │ 跨供应商分摊并发，  │
│             │ 模型，分散调用压力  │ 那 1 次调用  │ 避免单提供商限频    │
├─────────────┼─────────────────────┼──────────────┼─────────────────────┤
│ 融合 (Fusion)    │ 同时向所有成员并发  │ 极高！计费   │ 极高质量要求的复杂  │
│             │ 提问，裁判模型综合  │ N+1 次调用   │ 决策、审查、代码复核│
├─────────────┼─────────────────────┼──────────────┼─────────────────────┤
│ 决策路由 (Router)│ 轻量决策模型分析    │ 极低！仅多   │ 兼顾极致性价比与全能│
│             │ Prompt，挑最擅长者   │ 1次决策(可省)│ 表现，能力差异化池  │
└─────────────┴─────────────────────┴──────────────┴─────────────────────┘
```

### 1. 回退（Fallback — 按顺序尝试）
- 按照组合内排列的成员模型顺序依次发起请求；
- 第一个模型成功响应（200 OK 且有内容）则直接返回；
- 若第一个模型返回 429、5xx 报错、甚至返回 200 但内容全空，自动无缝尝试下一个成员。

### 2. 轮询（Round Robin — 轮流切换）
- 不总是从首个模型开始，而是根据请求计数动态轮换；
- 可配合组合粘性次数（Combo Sticky Limit），让每个模型处理固定笔数后顺移下一个。

### 3. 融合（Fusion — 面板 + 裁判）
- **工作流**：
  1. 同时向组合内**所有成员模型**并行发起相同的 Prompt 请求；
  2. 收集每个模型的不同解答作为候选面板（Panel）；
  3. 将所有回答打包交给指定的**裁判模型（Judge Model）**；
  4. 裁判模型取各家之长，综合输出最终答案。
- **注意**：每次对话会计费 $N+1$ 次调用（所有成员 + 1次裁判），成本最高，适合对生成品质要求苛刻的关键场景。

### 4. 决策路由（Router — 决策模型选成员）
- **工作流**：
  1. 在 System One 决策模型中指定一个作为**决策大脑**（如 `drex/drex-latest`、`oc/jev-1.13-free`、`v1m/rev-latest`）——它输出的是类型化概率而非文本，只负责选人、不参与回答；
  2. 用户 Prompt 进入后，决策模型分析意图（编程、长文档、数学推理等），结合各成员的能力标签（vision / tools / pdf / 上下文）选出最合适的一个；
  3. 被选成员置顶，其余成员保持原顺序——决策只决定"先试谁",不取消容错，选中成员失败仍会顺延；
  4. 仅执行被选中成员的那 1 次主要调用（外加一次廉价的决策调用）。
- **健康度**：成员近期失败会被标注为"recently flaky"并建议避开；**没有标记只表示"健康或暂无数据"，不是质量扣分**——新加入的成员不会因为没跑过而被低估。
- **优势**：兼顾速度与成本，在异构大模型混合池中实现自适应能力匹配。
- **注意**：决策失败、超时（默认 8s）或选中成员不可用时，静默回落到普通回退顺序，不影响可用性。
