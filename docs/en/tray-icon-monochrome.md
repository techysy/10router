# Monochrome Tray Icons — the macOS template alpha trap and Windows' dual theme registries

> Status: implemented and verified on real machines (2026-09-06, commits `3c5eb6cc` + `82fa807d`).
> Files: `desktop/main.js`, `desktop/make_icon.py`, `desktop/package.json`, `cli/src/cli/tray/{tray.js,trayWin.js}`.

## Background

The product has three tray surfaces: the CLI service tray (systray2 Go binary on macOS / PowerShell NotifyIcon on Windows) and the desktop-shell tray (Electron, all platforms). All previously used the colored brand icon (orange gradient rounded square + bold white "10"). Per platform convention — macOS menu bar icons are almost all monochrome template images that adapt to the menu bar appearance — the icons were switched to monochrome.

## Pitfall 1: macOS template images only use the alpha channel

Template rendering **ignores RGB and takes alpha only**, then fills black/white per menu bar appearance. The colored icon's alpha channel is a **filled rounded square** (the "10" is painted on top of the fill) — enabling template on it renders a solid blob. The old `isTemplateIcon: false` / `setTemplateImage(false)` was a workaround after hitting exactly this.

**Fix**: dedicated monochrome assets whose **alpha channel IS the artwork** (rounded-square outline + bold "10", transparent background), generated by `build_mono()` in `desktop/make_icon.py` (`MONO_STROKE = 7.5%` ≈ 2.4px at 32px; text at 40%). Products: desktop `icon-template.png` (16) + `icon-template@2x.png` (32, Electron picks @2x automatically), CLI `icon-template.png` (32, systray2 takes one base64 PNG), plus `icon-mono-white.ico` / `icon-mono-black.ico` in both directories for Windows. Template mode is enabled **on darwin only** (`isTemplateIcon` / `setTemplateImage(true)`); Linux keeps the colored icon — panels have no template convention and a white glyph vanishes on light panels. Desktop `build.files` lists the new icons explicitly; the CLI npm package ships all of `src/` automatically.

## Pitfall 2: Windows has two theme registries

Real-machine testing showed the icon stayed black after switching to a dark taskbar. Root cause — **Windows themes are two independent switches** under `HKCU\...\Themes\Personalize`:

| Value | Meaning | Used by |
|---|---|---|
| `SystemUsesLightTheme` | **Windows mode** → taskbar/Start menu appearance | the correct signal for a tray icon |
| `AppsUseLightTheme` | **App mode** → in-app content appearance | Electron `nativeTheme.shouldUseDarkColors` reads only this |

With the "Custom" mode (dark taskbar + light apps), `shouldUseDarkColors === false` → black glyph on a dark taskbar: invisible.

**Fix**: don't trust `nativeTheme` for the tray; `reg query SystemUsesLightTheme` directly (fallbacks: `AppsUseLightTheme` → `shouldUseDarkColors`). The CLI's `trayWin.js isWindowsLightTheme()` follows the same rule.

### Live switching

- macOS: free — template images re-render automatically.
- Windows: listen to `nativeTheme.on('updated')` (fires on WM_SETTINGCHANGE; both registry changes trigger it) and **rebuild the icon**, re-reading the registry — never cache the first decision.

## Fallback chain

Every path falls back to the colored brand icon (`icon.ico` → `icon.png`) when mono assets are missing, so stale/partial installs never show a blank tray.

## Verification

```powershell
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize"
```

Toggle Windows light/dark mode: the tray icon should flip black/white instantly; same for macOS appearance. `python desktop/make_icon.py` regenerates everything; eyeball `icon-template@2x.png`.

## Takeaways

1. **Template images require "alpha = artwork"** — enabling template on any colored icon yields a solid blob; you need dedicated line-art assets.
2. **On Windows, always ask first: do you follow the taskbar or the app?** The two registries are separate; `nativeTheme.shouldUseDarkColors` means app mode only.
3. For per-platform-convention assets like tray icons, a generator script (`make_icon.py`) beats hand-maintained PNG/ICO — one parameter change, all platforms regenerated.
