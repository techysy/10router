### 🐛 修复

- **组合模型选择器不再把「打折」显示成「免费」**：给组合挑模型时，千问办公国内版的 GLM-5.4（官方挂「首发上线」，1.2 倍）和 Ling-3.1-Flash（官方挂「限时1折」，0.1 倍）之前会显示成绿色 `free`——选择器把「有促销」当成了「免费」，而同一个模型在供应商详情页显示的是真实倍率，两个界面两个价格。现在免费只认真正的 0 倍率（MiniMax-M3.1-Flash、标准档这类官方限免行照旧亮 `free`），促销名称（「首发上线」「限时1折」「会员限免」）改放到悬停提示里解释价格从哪来，与详情页口径一致。另：官方客户端新挂的 MiniMax-M3.1-Flash「限免」在详情页本来就正确显示为 free（用真号实测官方目录确认，徽章数据源无需改动），在供应商详情页点「刷新模型列表」即可看到。

- **「余额优先」（小额优先 / 大额优先）现在真的会保存并生效**：在供应商详情页把调度偏好选成「小额优先」或「大额优先」后，界面上显示已选中，但实际请求仍按手动优先级打第一个号——保存这一步会把整张策略表按当前页面的快照整体写回，另一个标签页或后台任务刚写入的其它供应商策略会被连带覆盖，有时连自己这次的选择也一起丢掉（数据库里那一项根本不存在）。现在改成只写自己这一家、在数据库事务内合并，别人家的策略不再受影响。同时修好两处：全局调度设为「轮询」时不再压过某个供应商单独选的余额优先；从没手动刷过配额的账号现在也会自动补齐余额（此前这些号余额未知，一律排到最后，看起来就像余额优先没生效）。余额未知的账号仍按手动优先级排在已知余额之后。选中账号时运行日志会记一行 `balance-lowest-first selected …`（带账号与余额数值），可直接核对是否生效。适用于所有按余额调度的供应商（Meoo、千问办公、DeepSeek、SiliconFlow 等），不限某一家。

- **余额已用完的账号不再被「小额优先」排在最前面**：选了小额优先后，余额为 0（或已透支成负数）的账号会排到所有正常账号之后。此前它是「谁余额小谁先上」，于是 0 余额的号永远排第一，每个请求都要先撞一次上游的「额度不足」再换下一个号——既慢又多一次失败。现在这类号视为已用尽，沉到队尾，两个方向（大额优先 / 小额优先）都一样。余额未知的账号仍排在有余额的账号之后。

- **七家供应商的详情页新出现「大额优先 / 小额优先」**：QuWork、DuMate（百度搭子）、Lingxi（WPS 灵犀）、DeepAI、AutoClaw（智谱澳龙，国内版与国际版）、Clixad、FreePi —— 这七家的额度本身就是可按账号比较的积分/余额，此前它们的调度下拉里只有「到期优先 / 轮询 / 手动优先」三档，压根选不到余额优先。现在入口打开，行为与 Meoo、千问办公一致：默认仍是手动优先级，选「小额优先」就先烧余额少的号、选「大额优先」先烧余额多的号，且同样会在运行日志里记一行选中结果。（各家余额读数各自的口径不变：AutoClaw 读钱包合计，Clixad / FreePi 读每日 credits，Lingxi 读智点余额汇总行。）

- **MiniMax Code（国内版 / 国际版）的「到期优先」不再把快到期的号排到最后**：MiniMax Code 的算力币是按批次到期的（每批有自己的过期日），属于「一次性到期包」——到期优先的本意就是先把最近到期的批次烧掉再轮到别的号。但它此前被归进「余额类」调度，开了到期优先后反而走「红区下沉」逻辑：余量低于 5% 的号被排到队尾，结果余量最高的号（12-09 到期）先被烧，12-05 就到期的两批眼看要作废。现已在调度分类里改归「资源包」类（与 CodeBuddy / Qoder 同类）：到期优先严格选中最近到期的号，红区不再下沉。余额卡、积分提取、每日签到均不受影响。

- **Antigravity 的 Gemini 4 Hydrogen 现在真的能用了**：注册表里那三个「高/中/低」档位是按隔壁 Argon 家族的写法推出来的，上游从来没实测过——实测下来这三个 id（带不带括号写法）一律回 404「找不到该实体」，于是每次选中都会被扣一次 120 秒的按模型锁号再换号重试，组合里留着这一席就是每轮白打。我们拿自己的账号（3 个）实拉了上游目录：Hydrogen 在上游只有一个真实模型条目 `gemini-4-hydrogen-sonar`。现在三个档位 id 都改指向这个真实条目，档位本身照旧生效（走上游的思考档位参数，实测高/中/低分别思考 42/39/21 token 后正常出字），另外补上按上游规格对齐的窗口/输出/图片/视频/PDF 标注，并把不带后缀的 `ag/gemini-4-hydrogen` 也接上（按同系列惯例落到「中」档）。已经建好的组合、连接里的模型锁定不用改，直接就能用了。

- **Loomy 四个模型不再冒充能读图**：Loomy 的公开接口（Qwen 3.8 Flash、DeepSeek V4.1 Flash、DeepSeek V4.1 Flash 1017、GLM 5.3 Flash）此前被标成支持图片，但它的 Bearer 通道实际只认文本——带图请求要么直接报「请求有误」，要么返回 200 但模型只是把图片编码当文字读、答非所问。官方网页端的附件走的是另一套私有上传接口，当前接入方式够不到。现在这四款如实标为纯文本：组合收到图片时会自动让给真正能读图的成员，纯文本请求照常走 Loomy 不受影响。

- **Responses 转 Chat 的图片 detail 归一化（DuMate 400 修复）**：Codex 等 Responses 客户端发图片时会带 `detail: "original"`——这是 Responses API 的合法值，但只收 auto/low/high 的 Chat 上游（如 DuMate）会直接 400，模型还没跑就被拒。此前两条 Responses→Chat 转换路径都把这个值原样透传。现在统一归一化：auto/low/high 保留，缺失或非法值（含 original）一律落到 auto。任何包含 DuMate 成员的组合收到带图请求都不再因此报错；Chat→Responses 方向不受影响。

- **一次并行调用多个工具不再被粘成一个**：某些上游模型（实测 Qwen4-Max 系通道）在一次回多个工具调用时，流式分片的序号字段一直是 0，新调用只换了 id 和函数名。10Router 按这个序号归并，于是两个调用被粘成一个：函数名变成 `get_weatherget_time` 这种连写的怪名，参数变成两段 JSON 首尾相接（无法解析），客户端要么报参数错误，要么只执行第一个工具、第二个静默丢失。现在在流出入口按调用身份（新 id / 新函数名）切分，序号只在上游确实乱用时才修正：chat、Responses、Claude、Gemini 四种协议客户端都拿到正确拆开的调用。上游守规范（每个调用带递增序号，或后续分片不带 id/函数名）时行为一字不变。

- **组合排在前面的渠道「假死」时秒级换下一个，不再干等最约 249 秒**：组合按顺序试成员时，如果排前的成员上游只是把连接挂着、迟迟不给响应，网关以前会把它当成一次正常投递来等到底，还要在内部重试几轮（最坏约 249 秒才轮到下一个成员）——客户端自己的超时往往先到，用户看到的就是「整个组合卡死」而不是「降级到备用渠道」。现在组合试成员用的是专门的短探测预算（默认 12 秒，可用环境变量 `COMBO_PROBE_TIMEOUT_MS` 调整），探测也不再做内部重试（换下一个成员本身就是重试）；连续两次彻底没回应的成员会被临时记入「冷却」往后排，下一次请求直接先试健康渠道，不用再撞那个死位置（冷却只往后挪、不会把渠道踢出组合，全都不行时它仍作最后兜底；任何一次真实返回都会解除冷却）。直连单个模型的正常请求不受影响，等待上限照旧。

- **额度卡的倒计时与卡片排序口径统一**：额度跟踪器里，卡片头部写的「最早到期/重置」和沙漏钮（Resets first）排的先后，此前是各算各的——同一个账户可能卡上写「17d 后过期」，位置却按另一个日期排。现在两处取同一个值，并且头部不再漏掉**已用完但会回血**的周期额度：CodeBuddy 那张「每月 0/500」的包，卡上现在如实显示「每月 5d 后重置」，而不是只报还剩积分的资源包。反过来，已经烧完、日期只剩记录意义的一次性包不再冒充「最快到期」把账户顶到列表最前。供应商详情页与媒体供应商页的「最早到期」徽标同步按这个口径显示。

- **Qoder CN「快速」模型可正常对话**：官方目录只在较新的客户端版本下才下发「快速」这一档，我们读取目录时用的版本号偏低，导致它一直没被取到——选了「快速」的请求会报「model_config for "fast" not yet known」。现在目录按能取到该档的版本读取，聊天请求的签名保持不变。「快速」的倍率标注（×0.6）也一并补上。

- **DuMate 额度卡逐包明细不再堆叠后缀**：同名积分包此前会显示成「每日赠送积分·2·2·2·2·2·2·2」这样一层层加后缀的样子（每遇到一个重名就在末尾再贴一次标记），现在按顺序正常编号（每日赠送积分、每日赠送积分·2、·3…），一个月签到下来明细终于能读了。

- **0 积分的配额包不再参与倒计时**：额度卡逐包明细「已用完 / 已过期」段里，积分已用完但还没到期的包此前仍显示「Xh Ym后过期」倒计时——可它已经没有余额可消耗，这个倒计时是空转的。现在这类包的日期改显示为绝对的到期日（如「09-30 到期」），倒计时只留给还有余额的包；卡片头部的「N 个资源包（可用）」倒计时本就只统计有余额的包，不受影响。

- **升级安装不再弹「无法关闭」（Windows 安装包已原位替换更新）**：升级时新安装器自带清理、跳过旧版本冻结的旧卸载器代码，不再触发幽灵进程的无法关闭弹窗或静默退出码 2，用户数据不受影响。
- **中途夭折的流式请求不再留下一条「绿色 0 token」的假成功**（issue #48）—— 流式请求一开就写入占位记录，但那时还没产出任何内容、状态却已是「成功」。上游随后断链时，中止路径完全不碰数据库，那行记录再没人修正：一次被掐断的请求会在详情列表里一直显示成「已完成、且恰好没花钱」。现在进行中的记录就显示为进行中，被中止的流式请求记为失败。
- **单个模型失败不再把整条连接标记为「不可用」**（issue #46）—— 这才是根因：按模型的锁在写入时，会连带写一个账号级的「不可用」标志，而选路自始至终只看那把按模型的锁。于是兄弟模型照常工作、连接却显示为宕机。现在这个标志只在真正的账号级失败时才写。
- **CreditDaddy 三条线的 404 不再被报成「模型不存在」**（issue #47）：CreditDaddy 已把网关端点迁到带品牌名的路径（`/gateway/zcode/…` 等），404 说的是端点而不是你的模型。现在提示会直说这一点，卡片上也给出排查指引：路径要保留品牌段；若 CreditDaddy 版本早于这次改名（仍只提供旧的裸端点），应升级 CreditDaddy 而不是改那个输入框。
- **部分受限的连接改为显示黄色，不再标红**（issue #46）：只有一个模型在冷却期的连接仍在正常服务其它模型，现在有独立的「部分受限」状态，不再被当成整个账号宕机。同时把原先手写了四份、彼此可能不一致的状态判定收敛成一份。
- **单个模型的额度用完不再显示成「账号不可用」**（issue #46）：Google / Antigravity 的额度按模型分桶，我们的锁也是按模型的，但提示一律写「该账号额度已用完」——而同一连接上的其它模型在整个窗口内照常可用。现在提示会点名具体模型并说明其余模型不受影响；真正整账号耗尽的情况文案不变。
- **用量「概览」不再空白、而「详情」列着一堆 0 token 的行**（issue #48）：两个页签读的是不同的表，上游没回 token 数时，一侧整行被丢掉、另一侧却照样写进去（显示 0 输入 / 0 输出）。此前只有流式请求有估算兜底，非流式请求没有。现在两个页签显示同一组估算出来的数字。估算值只记进仪表盘——客户端拿到的 usage 仍严格是上游返回的原值。
- **超长上下文自动压缩默认触发比例 0.9 → 0.95**：自动压缩改为更贴近窗口上限才触发（阈值档位与总开关不变，可在「实验特性」卡片调整）。
- **Claude Code / mirasim 不再在 160K 处强行压缩**：模型列表此前只按 OpenAI 约定上报窗口，Claude CLI 读不到就回退到内置的 20 万默认值，于是 Qwen3.8-Max（真实 100 万）等模型在客户端侧 16 万 token 就触发压缩。现在补发 Anthropic 约定的字段，客户端能读到真实窗口。
- **仪表盘模型卡不再把 1M 窗口显示成 20 万**：Qoder（`qd` / `qdc`）、Kiro（`kr`）、CodeBuddy CN（`cbcn`）、Antigravity（`ag`）这四条线的模型此前在仪表盘上因按别名查能力而跌到 20 万地板（vision / reasoning 徽章也被剥掉），Kiro 的 gpt-5.6 系窗口还虚高到 105 万。现已全部归一化到正确的 1M 档。
- **Trae Free 卡片图标不再缺图**：本版接入时漏了图标资源，卡片回落成文字缩写、而其它屏又是另一张（彩色）标。现已统一使用从客户端 exe 提取的 Trae（SOLO）官方黑白标。
